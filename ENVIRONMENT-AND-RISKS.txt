中文
============================================================

1. 环境要求

- 操作系统：Windows 11 x64。
- 已验证环境：Windows 11 25H2（内部版本 26200）。
- 目标应用：必须已安装 Microsoft Media Player（媒体播放器）。
- 账户：需要可交互登录的普通 Windows 用户账户。
- 安装方式：按用户安装到 %LOCALAPPDATA%，通常不需要管理员权限。
- 运行方式：登录任务“DefaultAppGuard Agent”会启动后台 Agent。
- 进程模式：Agent 使用无控制台的 Windows 后台子系统，不应弹出或常驻终端窗口。
- 本地端口：Agent 仅监听 127.0.0.1:51873。
- 运行时：发布包是自包含的，不需要单独安装 Node.js 或 .NET。

2. 安装前必须了解

- 必须完整解压 ZIP，不能只从压缩包内直接运行安装程序或脚本。
- 请用随发布包提供的 SHA-256 文件核对下载文件。
- 安装器会根据 package-manifest.json 再次校验每个包内文件的大小和
  SHA-256，并拒绝文件缺失、混入或损坏的包。
- 普通用户应双击 DefaultAppGuard.Setup.exe。它使用当前用户权限且不显示终端。
  启动脚本前，Setup 的原生代码会独立核对清单、文件集合、长度和 SHA-256。
  对核验通过的包，Setup 只为自己的隐藏 PowerShell 子进程临时使用
  ExecutionPolicy Bypass，以便从网页下载并解压的完整包可以运行。该设置随
  子进程退出而消失，不会写入或修改当前用户、整台电脑或注册表中的执行策略，
  也不能覆盖公司或学校下发的组策略。事务安装器随后会再次核验同一包。
- 升级采用暂存、替换、就绪检查和失败回滚流程；只有新 Agent 解析到
  Microsoft Media Player、为每个受保护格式取得主 COM 查询证据，并通过进程身份和无控制台检查后
  才提交升级。已有默认应用漂移会被报告，但不会被误判为安装器故障。
- 当前 EXE、PowerShell 脚本和模块未使用受 Windows 信任的
  Authenticode 发布者证书签名。
- Windows SmartScreen、Smart App Control 或组织安全策略可能阻止未签名程序。
- 不要为了安装本程序而永久关闭系统安全功能或绕过组织策略。
- 建议在安装前查看 Install-DefaultAppGuard.ps1。

3. 代码签名、Windows 警告与安装安全判断

3.1 本版本的签名状态

- 适用本提示文本的 0.1.6 版本是“未签名 alpha 版本”。
- DefaultAppGuard.Agent.exe、DefaultAppGuard.Setup.exe、Install-DefaultAppGuard.ps1、
  Uninstall-DefaultAppGuard.ps1、Get-DefaultAppGuardDiagnostics.ps1 和
  DefaultAppGuard.Package.psm1 均没有受 Windows 信任的发布者签名。
- 因此，Windows 可能显示“未知发布者”“Windows 已保护你的电脑”
  “未进行数字签名”或类似提示。这些提示在本版本上可能是预期现象，
  但它们也意味着 Windows 无法通过代码签名确认文件由谁发布。
- 未出现警告不代表文件一定安全；出现“未知发布者”也不能单独证明文件
  是恶意软件。必须同时核对下载来源、版本和 SHA-256。

3.2 什么是代码签名

- 代码签名可以理解为软件文件上的“数字身份证和防拆封标记”。有效签名
  可以让 Windows 核对发布者身份，并检查文件在签名后是否被修改。
- 代码签名不能保证程序没有漏洞、绝不会误报，也不能代替杀毒软件。
- 本项目提供的 SHA-256 和包内清单主要用于检查文件是否与发布包一致；
  它们不是发布者身份证，也不能代替 Authenticode 代码签名。
- ZIP 文件名中包含版本号、GitHub 页面显示绿色标记，或者杀毒软件暂未
  报警，都不等于文件已经获得代码签名。

3.3 普通用户安装前检查清单

只有下面各项都满足时，才考虑继续安装本未签名 alpha 版本：

1) 下载页面必须是项目的官方 GitHub Releases：
   https://github.com/lycorismmoonlights/default-app-guard/releases
2) ZIP 文件名、页面版本和本文件顶部的“适用版本”必须一致。
3) 同时下载对应的 .sha256 文件，并核对 ZIP 的 SHA-256。可以在 ZIP
   所在文件夹打开 PowerShell，运行：

   Get-FileHash .\DefaultAppGuard-0.1.6-win-x64.zip -Algorithm SHA256

   输出的 64 位哈希必须与 .sha256 文件完全一致。任何一位不同都不要运行。
4) 完整解压 ZIP 后再安装，不要从压缩包预览窗口直接运行脚本。
5) 确认 Windows Defender 或其他安全软件没有报告木马、病毒、勒索软件
   或隔离事件。此类恶意软件警报不同于单纯的“未知发布者”提示。
6) 安装器正常情况下不需要管理员权限。如果它意外要求管理员账户、
   关闭杀毒软件、关闭防火墙或提供密码，应立即取消。

如果无法独立完成上述核对，建议不要绕过警告安装当前 alpha 版本，等待
以后受信任签名的版本，或请可信且具备 Windows 安全经验的人协助检查。

3.4 遇到 Windows 提示时怎么办

- 仅显示 SmartScreen“Windows 已保护你的电脑”或“未知发布者”：
  这与当前未签名状态相符，但不要立刻选择继续。先完成 3.3 的全部检查。
- Smart App Control 直接阻止运行且没有继续选项：
  不要关闭 Smart App Control。当前未签名版本可能无法在这台电脑上安装。
- 直接运行脚本时，PowerShell 提示“未进行数字签名”或执行策略禁止运行：
  不要把整台电脑的执行策略永久改为 Unrestricted 或 Bypass；请改用包内
  Setup。若通过 Setup 仍被策略阻止，通常表示组策略或安全产品优先级更高，
  应停止安装；组织管理的电脑应联系管理员。
- Windows Defender 或其他安全软件明确报告恶意软件、文件被替换或隔离：
  不要恢复、放行或继续运行。删除下载文件，并通过项目的 GitHub 安全报告
  渠道提交版本、下载地址、SHA-256 和警报名称。
- 系统要求输入管理员凭据，或提示来自公司、学校的策略限制：
  取消安装，不要尝试绕过。DefaultAppGuard 不能覆盖组织安全策略。

3.5 未来签名版本的判断方法

- 只有发布说明明确写明“已签名”，并列出预期签名者名称时，才应把该版本
  视为签名版本。不要把其他版本的签名状态套用到当前文件。
- 对 EXE，可以打开“属性”并查看“数字签名”选项卡；签名应存在、状态有效，
  且签名者名称应与该版本官方发布说明完全一致。
- 对 PowerShell 脚本和模块，应以官方发布说明及 Windows 的有效
  Authenticode 验证结果为准。
- 即使签名有效，仍必须从官方发布页下载、核对版本，并保留 Windows
  Defender。有效签名证明发布者身份和签名后的完整性，不代表零风险。

4. 实际工作机制

- 主查询算法使用 IApplicationAssociationRegistration.QueryCurrentDefault
  读取 Windows 当前实际生效的默认程序。
- UserChoice 注册表数据只作为交叉证据，不作为保底查询结果。
- 主监控算法使用 RegNotifyChangeKeyValue 监听当前用户的 FileExts 变化。
- Agent 会周期性重新执行 COM 查询，以减少遗漏变化的时间窗口。
- 程序只保存自己的监控范围、状态和安装信息。
- 程序不会直接改写 UserChoice，不会绕过 UCPD，也不会静默强制恢复默认程序。
- 需要修复时，程序会打开 Windows 官方“默认应用”设置，由用户确认修改。

5. 已知风险和限制

- 本版本为 alpha 预发布版本，不提供“永久锁定”或不可绕过的保证。
- 未签名发布物在部分电脑上可能无法运行，这是当前最大的推广限制。
- 包内逐文件哈希用于发现下载、解压或混包损坏；由于清单本身尚未由可信
  发布者签名，它不能证明发布者身份，也不能抵御能够同时替换文件和清单的攻击者。
- Windows 更新、Media Player 更新或注册机制变化可能导致误报、漏报或暂时失效。
- 注册表通知和周期复检之间存在有限时间窗口，变化不会被承诺为瞬时发现。
- 当前只保护视频扩展名，并且目标固定为本机动态解析到的 Microsoft Media Player。
- 当前只支持单个登录用户实例；不同 Windows 用户需要分别安装和配置。
- 后台 Agent 和计划任务会占用少量内存、CPU 和本地端口。
- Agent 是长期运行的后台进程；关闭应用页面不会停止监控。若出现 Agent
  控制台窗口，通常表示仍在运行 0.1.1 或更早版本，应升级并重新安装。
- 本地 API 只允许回环地址和受限 Origin，但同一用户会话中的恶意本地进程仍可能尝试访问它。
- 当前仅在上面列出的 Windows 版本上完成完整发布验证，其他 Windows 11 版本需要单独验证。
- 软件按“现状”提供，不附带无故障、无数据损失或适用于特定用途的保证。

6. 隐私与安全

- 当前版本不包含遥测、广告、云同步或主动外网请求。
- 状态和配置默认保存在 %LOCALAPPDATA%\DefaultAppGuard 下。
- Get-DefaultAppGuardDiagnostics.ps1 只生成经过约束的诊断摘要，不包含个人
  路径、注册表导出、运行时文件原文或令牌；公开前仍应由用户自行复核报告。
- 报告问题时不要公开令牌、完整注册表导出、个人路径或 runtime 目录中的原始文件。
- 安全问题请使用 GitHub 私密漏洞报告，不要在公开 Issue 中发布利用细节。

7. 卸载

运行：

& "$env:LOCALAPPDATA\Programs\DefaultAppGuard\Uninstall-DefaultAppGuard.ps1"

使用 -KeepData 可以保留监控范围和最近状态。

English

1. Environment requirements

- Operating system: Windows 11 x64.
- Fully validated environment: Windows 11 25H2, build 26200.
- Target application: Microsoft Media Player must be installed.
- Account: a normal interactive Windows user account is required.
- Installation: per-user under %LOCALAPPDATA%; administrator rights are
  normally not required.
- Startup: the "DefaultAppGuard Agent" logon task starts the background Agent.
- Process mode: the Agent uses the no-console Windows GUI subsystem and should
  not open or keep a terminal window visible.
- Local port: the Agent listens only on 127.0.0.1:51873.
- Runtime: the release package is self-contained and does not require a
  separate Node.js or .NET installation.

2. Before installation

- Extract the complete ZIP before running Setup or any script.
- Verify the download against the SHA-256 file supplied with the release.
- The installer additionally validates the size and SHA-256 of every packaged
  file against package-manifest.json and rejects missing, mixed, or damaged
  payloads.
- Non-technical users should double-click DefaultAppGuard.Setup.exe. It runs
  with current-user rights and no terminal. Before starting any script, native
  Setup code independently verifies the manifest, file set, lengths, and
  SHA-256 hashes. For a verified package, Setup uses ExecutionPolicy Bypass
  only in its hidden PowerShell child so a complete web-downloaded package can
  run. The value disappears with that child and does not write or change the
  current-user, computer, or registry policy. It cannot override company or
  school Group Policy. The transactional installer verifies the package again.
- Upgrades use staging, replacement, readiness verification, and rollback. The
  upgrade is committed only after the new Agent resolves Microsoft Media
  Player, produces primary COM-query evidence for every protected format, and passes process-identity and
  no-console checks. Existing association drift is reported but is not treated
  as a setup failure.
- The current EXE, PowerShell scripts, and module do not carry an
  Authenticode publisher signature trusted by Windows.
- Windows SmartScreen, Smart App Control, or organization policy may block
  unsigned software.
- Do not permanently disable Windows security controls or bypass organization
  policy to install this application.
- Review Install-DefaultAppGuard.ps1 before running it.

3. Code signing, Windows warnings, and safe installation decisions

3.1 Signing status of this version

- Version 0.1.6 covered by this notice is an unsigned alpha release.
- DefaultAppGuard.Agent.exe, DefaultAppGuard.Setup.exe, Install-DefaultAppGuard.ps1,
  Uninstall-DefaultAppGuard.ps1, Get-DefaultAppGuardDiagnostics.ps1, and
  DefaultAppGuard.Package.psm1 do not have a publisher signature trusted by
  Windows.
- Windows may therefore display "Unknown publisher", "Windows protected your
  PC", "not digitally signed", or a similar warning. These messages may be
  expected for this version, but they also mean Windows cannot use code signing
  to confirm who published the files.
- No warning does not prove that a file is safe. An "Unknown publisher" warning
  alone also does not prove that a file is malicious. Check the download
  source, version, and SHA-256 together.

3.2 What code signing means

- Code signing is similar to a digital identity and tamper-evident seal on a
  software file. A valid signature lets Windows check the publisher identity
  and whether the file changed after it was signed.
- A signature does not guarantee that software has no bugs, will never trigger
  a false positive, or can replace antivirus protection.
- The project's SHA-256 file and per-file package manifest mainly check whether
  files match the release. They are not a publisher identity and do not replace
  Authenticode code signing.
- A versioned ZIP name, a green indicator on a GitHub page, or the absence of
  an antivirus alert does not mean the files are code-signed.

3.3 Pre-installation checklist for non-technical users

Consider installing this unsigned alpha only when every item below is true:

1) The download page is the project's official GitHub Releases page:
   https://github.com/lycorismmoonlights/default-app-guard/releases
2) The ZIP name, release-page version, and "Applies to version" value at the
   top of this file all match.
3) Download the matching .sha256 file and verify the ZIP. Open PowerShell in
   the folder containing the ZIP and run:

   Get-FileHash .\DefaultAppGuard-0.1.6-win-x64.zip -Algorithm SHA256

   The 64-character hash must match the .sha256 file exactly. Do not run the
   package when even one character is different.
4) Extract the complete ZIP before installation. Do not run scripts from an
   archive preview window.
5) Confirm that Windows Defender or another security product has not reported
   a trojan, virus, ransomware, or quarantine event. A malware alert is
   different from an "Unknown publisher" warning.
6) The installer normally does not require administrator rights. Cancel if it
   unexpectedly asks for an administrator account, antivirus or firewall
   shutdown, or a password.

If you cannot independently complete these checks, do not bypass warnings to
install the current alpha. Wait for a future release with a trusted signature,
or ask a trusted person with Windows security experience to inspect it.

3.4 What to do when Windows shows a warning

- SmartScreen shows only "Windows protected your PC" or "Unknown publisher":
  this is consistent with the current unsigned status, but do not immediately
  continue. Complete every check in section 3.3 first.
- Smart App Control blocks the file and offers no continue option:
  do not turn off Smart App Control. The current unsigned release may not be
  installable on that computer.
- When a script is run directly, PowerShell says it is "not digitally signed"
  or execution policy blocks it:
  do not permanently change the computer-wide policy to Unrestricted or
  Bypass; use Setup from the package instead. If Setup is still blocked, a
  higher-priority Group Policy or security product is probably enforcing the
  rule. Stop; on a managed computer, contact the administrator.
- Windows Defender or another product explicitly reports malware, replacement,
  or quarantine:
  do not restore, allow, or run the file. Delete the download and use the
  project's GitHub security-reporting channel to provide the version, download
  URL, SHA-256, and alert name.
- Windows requests administrator credentials or reports a company or school
  policy:
  cancel the installation and do not attempt a bypass. DefaultAppGuard cannot
  override organization security policy.

3.5 How to identify a future signed release

- Treat a version as signed only when its release notes explicitly say
  "signed" and name the expected signer. Do not apply the signing status of one
  version to files from another version.
- For an EXE, open Properties and inspect the Digital Signatures tab. The
  signature must exist, be valid, and name the same signer stated in the
  official release notes.
- For PowerShell scripts and modules, rely on the official release notes and a
  valid Windows Authenticode verification result.
- Even with a valid signature, download only from the official release page,
  confirm the version, and keep Windows Defender enabled. A valid signature
  proves publisher identity and post-signing integrity, not zero risk.

4. What the application actually does

- The primary query algorithm uses
  IApplicationAssociationRegistration.QueryCurrentDefault to read the
  effective Windows default handler.
- UserChoice registry data is cross-evidence only, never a fallback result.
- The primary monitor algorithm uses RegNotifyChangeKeyValue on the current
  user's FileExts tree.
- The Agent periodically repeats the COM query to reduce missed-change windows.
- The application writes only its own monitored scope, status, and install data.
- It does not write UserChoice, bypass UCPD, or silently force a default app.
- Repair opens the official Windows Default Apps surface for user approval.

5. Known risks and limitations

- This is an alpha prerelease. It does not provide an unbreakable hard lock.
- Unsigned artifacts may be blocked on some computers. This is the largest
  current distribution limitation.
- Per-file package hashes detect download, extraction, and mixed-package
  corruption. Because the manifest is not yet signed by a trusted publisher,
  it does not prove publisher identity or resist an attacker who can replace
  both files and the manifest.
- Windows or Media Player updates may cause false positives, false negatives,
  or temporary incompatibility.
- A limited detection window exists between registry notifications and
  periodic readback; instant detection is not guaranteed.
- The current version protects video extensions only and targets the locally
  resolved Microsoft Media Player installation.
- One instance is supported per signed-in user. Each Windows user must install
  and configure the application separately.
- The background Agent and scheduled task use a small amount of memory, CPU,
  and one loopback port.
- The Agent is a long-running background process; closing the application page
  does not stop monitoring. A visible Agent console normally means version
  0.1.1 or earlier is still installed and should be upgraded.
- The API is loopback-only with restricted Origins, but a malicious local
  process in the same user session may still attempt to access it.
- Full release validation has only been completed on the Windows build listed
  above. Other Windows 11 versions require separate validation.
- The software is provided "as is", without warranties of uninterrupted
  operation, no data loss, or fitness for a particular purpose.

6. Privacy and security

- The current version contains no telemetry, advertising, cloud sync, or
  proactive outbound network request.
- Configuration and status are stored under %LOCALAPPDATA%\DefaultAppGuard.
- Get-DefaultAppGuardDiagnostics.ps1 produces a constrained diagnostic summary
  without personal paths, registry exports, raw runtime file contents, or
  tokens. Users should still review the report before publishing it.
- Do not publish tokens, full registry exports, personal paths, or raw runtime
  files in bug reports.
- Report security issues through GitHub private vulnerability reporting rather
  than publishing exploit details in a public issue.

7. Uninstall

Run:

& "$env:LOCALAPPDATA\Programs\DefaultAppGuard\Uninstall-DefaultAppGuard.ps1"

Use -KeepData to retain the monitored scope and latest status.
